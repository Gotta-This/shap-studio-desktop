# 科研数据工具集 · Vue V3

当前开发主线为 `master`，Qt v1.1.2 源码位于 `master-qt`，原有临时开发分支已迁移到主线。V3 使用 Vue 3、TypeScript、shadcn-vue / Reka UI、Tailwind CSS 4 和 Tauri 2，继续复用 Python 科学计算模块，安装包使用独立发布流程。

## 运行

需要 Node.js 22.12+，以及 Python 3.12。Tauri 开发还需要 Rust 与对应系统的原生构建工具。

```sh
cd vue_app
npm ci
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python scripts/prepare-python.py
export RESEARCH_V3_PYTHON="$PWD/.venv/bin/python"
npm run dev
```

访问 `http://127.0.0.1:1420`。Windows 的 Python 路径为 `.venv/Scripts/python.exe`。浏览器通过本机 Vite 桥接调用 Python；开发服务仅监听 127.0.0.1，检查 Host / Origin，并拒绝跨站写入。`npm run preview` 仅展示静态构建，不带 Python 桥接，功能验收应使用 `dev` 或 Tauri。

开发服务和正式应用未指定测试配置时，都使用用户隐藏目录；可以用 `RESEARCH_V3_PROFILE` 指向独立测试配置。本地自动化测试使用 `vue_app/.v3-data` 下的隔离目录。旧 V3 应用数据会保留到新位置，前端不再提供 Qt 数据迁移入口。用户选择已有稿件工作空间后，会读写该目录的 `.manuscripts.sqlite3` 和实际文件；请避免两个版本同时使用同一空间。

## 桌面运行与打包

```sh
# 开发：前端与 Python 源码均在本机；不会要求预先准备随包二进制
npm run desktop:dev

# 分发：先把 Python 与科学依赖打成当前系统的 sidecar
.venv/bin/python scripts/build-sidecar.py
python scripts/test-packaged-engine.py src-tauri/binaries/research-python-aarch64-apple-darwin
npm run desktop:build
```

打包时 Vue 编译为静态文件。安装后的 Tauri 应用通过 Rust 调用随包的 `research-python`，不启动 Node 服务，不要求用户另装 Node 或 Python。不同系统与 CPU 架构必须分别构建；Windows 随包文件带 `.exe`。`src-tauri/binaries` 的二进制不提交到 Git。当前 Mac 构建用于本地预览，没有开发者证书签名或 Apple 公证。

## 已接通的页面与操作

- 工作台：真实任务、待办与收件箱概览，科研工具快捷入口。
- 稿件总览：客户 / 状态 / 日期 / 未完成筛选，全文搜索、显示列、排序和分页。
- 任务详情：真实目录与改名，五类材料、文件搜索、预览、系统打开、分类、丢失后校验恢复，关联待办和操作记录。
- 新建 / 编辑：客户、名称、标签、状态、截止日期、备注及第一项待办，服务端复用 Qt 已验收的事务逻辑。
- 收件箱：接收、选择、归档；无冲突时从操作记录撤销归档。
- 待办：稿件与个人待办、优先级、日期、完成状态、编辑、软删除和撤销，返回关联稿件。
- 日期：shadcn-vue Calendar / Popover，中文月历、年月选择、手输校验、今天 / 明天 / 清除，Esc 与点击外部取消。
- 科研工具：类别抽样、均数标准差模拟、Word 汇总表识别及模拟 Excel、SPSS CROSSTABS 列联表统计、MedCalc 风格平均值对比（独立样本 t 检验）、截图与标注、SHAP 数据 / 模型 / 图表参数和实际计算。各模块独立保留参数与结果。
- 待办页支持桌面待办小组件：桌面版可打开或关闭置顶小窗口，勾选状态与主应用实时同步。
- 设置：选择本机目录、显示并打开应用数据目录、V3 更新检查、对应系统安装包下载、SHA256 校验和打开安装包；检查失败可重试。启动自动检查，安装前等待当前计算完成。

浏览器可上传 32 MB 内的材料；桌面导入使用原生文件选择与文件路径。预览是只读的，DOCX 提取文字，图片与 PDF 内嵌展示，其他格式交由系统程序打开。任务、收件箱和图表均使用原 Python 引擎，不把设计稿里的示例状态当作保存结果。

## 功能范围

科研工具第 3、4 项以当前 Qt 应用为功能依据，替换了旧 Penpot 设计中的简化流程：

- Word：五个页面（基础资料、表格匹配、文字匹配、全部字段以及来源、生成与导出）；导入前扫描原表与候选组别，可编辑识别草稿，确认组别后应用。例数默认 70，Word 例数和结局比例显式选择采用。支持无分组竖表、按原表分块编辑字段规则、正文独立编辑与冲突确认、配置保存恢复、完整 Excel 导出及后台计算取消。
- 模拟生图：四个页面（数据、模型与分类变量、样式、结果）；连续/分类变量独立表格与顺序、完整模型参数、公共样式与六类图独立继承、实际预览与已有模型重绘、结果表分页、图像放大保存和按内容选择复制/打包。数据或模型变化后，重绘要求重新完整分析。
- 运行中切换模块保留参数、进度和结果。关闭窗口会退出应用，已经接受的保存与后台任务由 Python 引擎完成；取消为协作式，当前引擎步骤完成后生效。

本轮已使用项目内 18 份 Word 完成 36 组 Qt/V3 配置与校验对照，并验证完整浏览器流程及打包引擎。详细覆盖、修复项与边界见 [Qt 对照检查记录](QA_QT_PARITY.md)。V3 采用与 Qt 类似的安装包更新方式：Windows 打开 NSIS 安装向导，Mac 解压后替换应用。不是静默热更新。个人分发包暂无商业签名或 Apple 公证。原生窗口与系统对话框未使用用户桌面进行点击测试。

当前 Vue 独立验收见 [QA_CURRENT_VUE.md](QA_CURRENT_VUE.md)。早期 Qt 对照记录保留为历史参考，不再作为 V3 的功能验收标准。

GitHub 托管系统标签依据 [GitHub runner 文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-where-workflows-run/choose-the-runner-for-a-job)；Windows 安装包内嵌 WebView2 离线安装程序，见 [Tauri Windows 安装文档](https://v2.tauri.app/distribute/windows-installer/)。

## V3.0.1 修订

V3.0.0 的桌面主程序错误地使用自身 Cargo feature 判断 Tauri 运行环境，发布时 CLI 开启的是依赖的 production feature，导致主程序尝试调用构建机器上的开发脚本。V3.0.1 改用 `tauri::is_dev()`，并在发布命令显式开启 production feature。原生返回的字符串错误统一转成 Error，界面可以显示真实原因并重试。

发布后测试现在运行的是 app 的 `research-studio-v3`（Windows 为 `.exe`），通过 `--bridge-request` 在不创建窗口的情况下调用与界面完全相同的 Rust → Python 函数。测试故意将开发 Python 指向不存在的路径，验证实际启用随包 Python、版本一致、中文待办以及数列、数值、Word、SHAP 四项后台任务。此检查可以发现“Python 引擎单独能用、桌面却未接通”的问题。

侧栏收起宽度不再被窄屏媒体规则覆盖；小于 700px 时自动紧凑导航。页面滚动由固定的应用容器管理，防止 WebKit 打开弹窗后切换视口宽度和媒体规则。搜索框回归使用传统滚动条并逐帧比较位置、宽度和内边距，覆盖 Chromium 与 WebKit。

V3.0.0 的桥接错误也影响应用内检查更新，升级至此修订版时请直接下载 Release 安装包替换。原有 V3 用户数据和已选择的工作空间保持兼容。

## 第五个工具：临床二分类预测模型分析

导入 XLSX / CSV，选择工作表，映射编号列和二分类结局列，确认阳性结局与候选指标。指标支持连续数值和分类变量。编号缺失／重复、结局缺失或不是二分类会阻止分析。默认按结局分层随机划分 70%／30%，也可指定训练例数；界面与导出记录均报告实际比例。

模型可选 LR、RF、XGBoost、SVM；训练集内分层五折网格搜索，以 AUC 选参。缺失值填补、标准化、分类编码在每个训练折内部拟合。验证集仅最终评价。默认分类阈值 0.5，可在运行前设置；取消操作在当前计算步骤完成后生效。

输出训练／验证双面板 ROC、H-L 分组校准图及同一 LR 模型列线图（未选 LR 时省略）。完整 ZIP 包含 650 DPI PNG、矢量 PDF、结果 Excel、H-L 分组明细、逐例预测概率与划分名单、最佳参数、输入哈希和环境／配置记录。AUC 置信区间采用 300 次 Bootstrap。H-L 分组少于三组不报告 χ²/P，低期望频数会提示；Brier 表示整体概率误差。训练集为表观性能，留出验证为内部验证。

首次安装依赖后运行 `python scripts/prepare-python.py`，macOS 会在私有 Python 环境内准备 XGBoost 所需 libomp，不修改系统库。中文绘图使用系统宋体或 Noto CJK；Linux 开发环境需安装 `fonts-noto-cjk`。当前支持最多 50,000 行、300 列、60 个选中指标、每个分类指标最多 30 个水平。输入文件保存在应用数据目录的 `profile/prediction/`；正式默认目录以设置页显示为准。

这是一套二分类建模工作流，变量是否适合研究目的、采集时间是否早于结局，仍需要用户在变量核对页确认。它不会自动追求指定 AUC 或修改原始病例记录。

### 第五个工具的图表设置

右上角“图表设置”提供公共样式、模型与图例顺序、ROC、校准图、LR 列线图、指标顺序与颜色、完整 JSON 七个面板。支持 DPI、预览 DPI、PNG/PDF/SVG、透明背景、字体字号、模型显示名／颜色／线型／标记、面板布局与编号、标题图注位置、坐标范围／刻度／旋转／网格、参考线、图例模板／位置／列数／边框／精度，以及列线图指标轴名称／颜色／顺序／分类标签／自定义刻度和积分轴样式。单图可覆盖公共设置。

“保存为默认”将样式保存在用户 profile 下的 `prediction-style.json`；“导出样式／载入样式”用于跨研究复用。修改后可“应用并重新绘图”：复用 `plot-data.json` 冻结快照，不再次训练或划分数据，新建结果版本，原有 Excel 指标与病例概率保持不变。ZIP 同时记录实际图表配置。旧结果若没有绘图快照，需要先重新分析一次。

风险刻度默认在可见刻度不足时自动补充，可关闭该选项以严格使用自定义列表。连续指标刻度限制在本次训练数据范围内。像素、文件名、字体和模板格式有输入检查，避免产生不可用文件。PDF/SVG 为矢量格式，DPI 主要影响 PNG 和可能的栅格化内容。

### LR 参考版式与可选分析

LR 列线图使用参考图中的独立坐标尺度：Points 和 Total Points 都占满绘图区，变量轴按相对贡献占用顶部积分轴，Risk 仅连接本次模型范围内的概率刻度并与总积分严格对应。默认使用输入列顺序、黑色细线、整洁刻度和自动高度；旧配置可在“LR 列线图”中点击“应用参考图版式”。范围、方向、总积分和概率均由当前 LR 模型计算，不复制样例数值。

“设置模型”增加两个默认关闭的选项：

- **LASSO 筛选诊断**：只使用训练集，折内填补／分类编码／标准化，执行分层五折 CV；输出系数路径、平均二项偏差及标准误、非零原始指标计数、λ 最小误差／一个标准误／数量约束建议。可设置 λ 范围、网格数、规则和迭代参数。分类哑变量按原指标归组计数。LASSO 不自动筛掉四模型的输入列。λ 定义为平均负对数似然中的 L1 系数，实际 `C=1/(当前训练折例数×λ)`。
- **SHAP 解释**：选择本次已训练的 XGB、RF 或 LR；可指定训练／验证／全量汇总、样本上限和单病例编号。输出蜂群、重要性、瀑布和力图组合图。XGB/LR 使用对数优势，RF 使用概率贡献；独热编码贡献相加回原始临床指标。输出前核对基线与贡献之和等于模型输出，并核对对应预测概率。力图分别叠放正／负贡献，避免混合符号时互相遮盖。

图表设置新增 LASSO／SHAP 面板，支持公共风格覆盖、各自标题／配色／图例／指标顺序／点线样式等。启用后，完整 ZIP 和 Excel 额外包含 LASSO 路径与逐折统计、筛选建议、SHAP 逐例贡献、重要性及单病例明细；“仅重新绘图”复用快照，不重复选择变量或计算 SHAP。

## 桌面布局工具与 360 数据副本（v3.2.3）

第六个工具增加“启用桌面布局工具”总开关，保存后生效并跨启动保留。关闭时停止手动备份、自动备份及布局恢复；保留历史记录及管理入口。“启用自动备份”独立控制定时任务，默认每 10 分钟一次，保留 144 份普通记录，永久记录不参与清理。

在当前 Windows 登录会话中检测 360 Desktop/Lite/Plus 常见桌面进程，结合卸载注册表和 `%AppData%/360DesktopLite` 数据目录显示检测状态。仅安装或残留数据不代表正在运行。运行时，手动与自动备份记录同时包含系统 Shell 可读取的图标位置和 360 数据目录压缩副本；未运行时只保存原生布局。检测失败或复制失败明确记录部分失败，已保存的原生布局不会因此丢弃。

360 文件保存到 `desktop-layouts/360-data/<内容哈希>.zip`，对应 JSON 的 `assistant.archive` 指向该副本。副本保持相对文件名与原始内容，不解析或编辑私有配置，不遍历桌面文档本体；副本可能包含 360 自身保存的历史配置及其他数据。相同文件名及内容共用副本；永久保留、普通份数清理、手动删除按记录引用管理副本。目录内文件总量限制 128 MB / 10000 个，链接、重解析点、不可读文件或复制过程中变化会导致本次同步失败，不会将不完整副本标为成功。

这是运行中原文件副本，不是调用 360 自带备份功能，也不保证第三方数据库的事务一致性。复制后复核目录与内容只能检查普通文件变化，不能替代 Windows 上的实际 360 恢复验证。含 360 副本的记录提供独立的“恢复 360”按钮。可在 360 运行中预览并确认恢复。先校验副本，再通过 Windows Restart Manager 正常退出当前用户会话中的已识别桌面进程（RmShutdown 标志为 0，不启用强制退出，不注册或操作服务、Explorer 或安全卫士）。按进程 PID、创建时间和程序路径绑定确认；退出时允许 360 保存最新配置，退出后的完整数据目录留作回退副本。写入后优先 RmRestart，未注册重启的应用则尝试原可执行文件；不会执行用户提供的命令或不匹配的程序。未能正常退出时不覆盖；配置已恢复但启动失败时单独提示手动打开。原本关闭的 360 保持关闭。恢复前重新检查进程和当前文件指纹，验证 ZIP 路径、大小、CRC 和内容哈希；解压到同级临时目录，再将当前数据目录整体改名为 `.360DesktopLite-before-restore-<随机标识>` 留作回退，然后换入恢复目录并复核内容。写入失败会尝试自动回退；回退失败明确显示原配置目录位置。回退目录不参与普通历史备份清理，成功后可通过提示中的按钮打开。恢复日志仅记录事件、数量和错误类型，不写入文件名或回退路径。文件恢复和检测到进程启动不等于已经验证实际布局，仍需人工核对屏幕；副本中的设置及其他历史数据也会一起恢复。360 运行时也允许单独恢复 Windows 原生布局，不退出 360、不修改其配置，确认框与恢复结果明确显示操作范围；检测到第三方管理程序或状态不明时延迟复核坐标，避免立即落位后又被改回却报告成功。Windows 自身开启自动排列、屏幕无法容纳等原有校验仍保留。原生备份记录当时可读取的排列，无法推导未曾保存的“启动 360 前布局”。360 自定义安装/其他进程名或其他数据目录需要后续适配。

备份列表默认每页 20 条，可选择 20 / 50 / 100 条，提供首页、上一页、下一页和末页。切换每页数量回到第一页；新增备份回到第一页；删除、自动刷新与份数清理后页码收敛到有效范围，避免空白页。

正常退出和重新启动接口参考：[RmShutdown](https://learn.microsoft.com/windows/win32/api/restartmanager/nf-restartmanager-rmshutdown)、[RmRestart](https://learn.microsoft.com/windows/win32/api/restartmanager/nf-restartmanager-rmrestart)。

验证：`python -m unittest discover -s vue_app/python -p test_desktop_layout.py`；`cd vue_app && npx playwright test tests/desktop-layout.spec.ts`。单元测试使用临时合成配置和模拟进程，不读取用户实际 360 数据；浏览器使用无头模式及桥接模拟。实际 Windows 360 进程、文件锁和恢复兼容性需在装有 360 的 Windows 机器验收。
