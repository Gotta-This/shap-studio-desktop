# Vue V3 与当前 Qt 对照检查记录

检查日期：2026-11-02。代码位于 `codex/vue3-v3-ui`。

## 方法与数据

- 当前 Qt 控件实际运行于 `QT_QPA_PLATFORM=offscreen`，通过其导入、确认组别及配置读取接口核对。
- Vue 使用独立无头浏览器点击操作；桌面保存使用模拟宿主对话框，文件写入仍通过真实 Python 接口执行。
- 使用本机项目 `word/` 下 12 份 DOCX、6 份旧 DOC。旧 DOC 使用独立配置的无界面 LibreOffice；转换、生成和导出均使用副本或临时目录。
- Qt 对照脚本逐份校验原文件 SHA-256 未变化。原文、作者文件名及完整测试数据仅保存在本机忽略目录，不提交到仓库。
- 测试不调用 System Events，不移动系统鼠标、不发送系统键盘事件、不激活用户应用窗口。

## 已修复的问题

1. 旧 DOC 转换结果原先位于桥接进程的临时目录，进程退出后无法确认组别；现先保存规范化 DOCX 到导入会话。
2. 文件上传误用了任务名称的 100 字/240 字节限制；现使用文件名规则，实际 101 字、243 字节原稿已通过。
3. 浏览器请求和 Python 响应按 Buffer 分块直接转字符串，可能截断中文/emoji，导致字段名损坏、组间无法配对；现使用流式 UTF-8 解码，并保留按字节计数的请求上限。
4. 编辑规则会重排字段、误清其他组确认状态；现同步类型、分类与标签，保留各组数值、确认状态和列顺序，保存完成后一次应用。
5. 字段弹窗补齐数值、分类比例、派生来源和汇总发生率的校验；派生引用随重命名同步，删除来源时一起清理依赖字段。
6. 无效/过期正文现在保留独立表格来源，并列出待核对正文。配置重新载入保留原文、研究选择和过期状态；关闭正文采用后可恢复基础列编辑。
7. 未确认新导入的 Word 时阻止生成旧配置；配置载入时清理旧导入会话，避免混用原表。
8. 补齐组别匹配明细和未匹配组名提示；无分组例数缺失时要求填写，不默用 70。
9. SHAP 单图预览不再显示另一张图；快速切换结果页不接受过期返回。补齐训练/测试行数、迭代次数、颜色核对和运行提示。
10. 补齐数值生成取消及初始请求期间的取消排队；复制/导出采用生成时的精度与参数快照，并增加类别计数、目标与实际核对。
11. 补齐首项待办的独立截止日期和优先级，以及材料导入/归档的新待办优先级；材料预览忽略过期请求。
12. Mac WebView 默认没有浏览器下载处理器，现改用原生保存对话框及原子文件写入。真实保存适配器和完整文件内容已测试；测试期间未弹出真实系统对话框。
13. 结果预览改为有界滚动区域、固定表头和横向展开列，避免组名竖排或数百行撑长页面；来源表头使用中文名称。
14. 开发服务忽略测试和运行产物目录，生成/导出及测试写入不再触发页面重载而丢失状态。

## 复现

在 `vue_app/` 下使用已安装依赖的 Python 3.12 和 Node.js 22：

```sh
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/audit-qt-corpus.py
.venv/bin/python -m unittest discover -s python -p 'test_*.py' -v
npm run build
npm test
.venv/bin/python scripts/build-sidecar.py
.venv/bin/python scripts/test-packaged-engine.py src-tauri/binaries/research-python-aarch64-apple-darwin
```

Qt 对照需要 PySide6；测试旧 DOC 需要无界面的 LibreOffice。没有本机语料或对照报告的 CI 不执行私有文档用例。完整文档记录、生成副本及日志位于 `.v3-data/audit-qt-corpus/`，浏览器截图和追踪位于 `test-results/`。

## 边界

本次覆盖本机语料、当前已有自动化流程和 Mac 打包引擎，不能据此声称任意 Word 文档均可无人工确认生成。截图型统计内容没有新增 OCR 能力。Windows 原生窗口、真实保存对话框的人工操作以及 V3 签名自动更新仍需专项验收；设置中的正式版查询不作为 Vue 安装包自动更新能力。
